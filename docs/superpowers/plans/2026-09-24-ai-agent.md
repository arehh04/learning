# AI Agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Activate the `owner_type = 'ai'` stub — Claude drafts a reply, Jev gates it on calibrated confidence, and the conversation either sends automatically or hands off to a human with the rejected draft shown as a pre-filled hint.

**Architecture:** Two thin HTTP adapters (`ClaudeAdapter`, `JevAdapter`, same pattern as the existing `TelegramAdapter`) feed one orchestrator (`AiReplyService`) that runs inside a queued job, triggered from `MessageIngestionService` whenever a message lands on an AI-owned conversation. `ConversationRoutingService` now defaults new conversations to `ai` ownership (was always `unassigned`), gated by a kill switch.

**Tech Stack:** Laravel (existing app), PHPUnit, `Http::fake()` for both external APIs — no live Claude/Jev calls in tests.

**Spec:** `docs/superpowers/specs/2026-09-24-ai-agent-design.md`

## Global Constraints

- No PHP SDK exists for Jev (Python/JavaScript only) — call `https://api.typesafe.ai/v1/systemone` directly via `Http::post()`, same convention as `TelegramAdapter`.
- Every AI-pipeline failure mode (Claude error, Jev error, low score, exhausted job retries) resolves to the same fail-safe: hand the conversation to a human. Never a stuck conversation, never an uncaught exception crashing the job.
- Handoff is one-way — once a conversation leaves `ai` ownership, nothing in this plan routes it back automatically.
- `AI_AGENT_ENABLED=false` must flip new-conversation routing back to `unassigned` with no code change — it's a production kill switch.
- Business rules and RAG are explicitly out of scope. The system prompt is one hardcoded string; do not build configuration UI, a knowledge base, or retrieval logic.
- All Claude/Jev calls in tests use `Http::fake()` — no live external API calls in the test suite.

## Review Focus

- **Empty or blank Claude draft** — a reasonable person expects the system never sends a blank message to a real customer; treated as a drafting failure (same fail-safe as an API error), not sent. Test in Task 2.
- **A human claims the conversation while Claude/Jev are still being called** (both are multi-second external calls) — a reasonable person expects the AI's now-stale work to be discarded, not to silently auto-send into a conversation a human is already handling. Test in Task 4.
- **A long-running conversation thread sent to Claude** — unbounded history risks hitting the API's context limits and crashing instead of degrading gracefully; capped to a bounded recent window. Test in Task 2.
- **Multiple rejected AI drafts accumulate on one conversation** before a human ever claims it — the inbox must pre-fill with the most recent draft, not an arbitrary or oldest one. Test in Task 6.
- **Jev responds with `200 OK` but a malformed or missing `noul` field** (not a network failure — a shape mismatch) — a reasonable person expects this treated as a confidence-check failure (fail-safe to handoff), not an uncaught type error crashing the job. Test in Task 3.

```php
<?php

namespace App\Services\AI;

use App\Exceptions\AI\AiDraftingFailedException;
use App\Models\Conversation;
use App\Models\Message;
use Illuminate\Support\Facades\Http;

class ClaudeAdapter
{
    private const MAX_HISTORY_MESSAGES = 20;

    private const SYSTEM_PROMPT = 'You are a helpful customer support assistant. Answer the customer clearly and concisely based on the conversation so far.';

    public function __construct(
        private readonly string $apiKey,
        private readonly string $model,
    ) {
    }

    public function draft(Conversation $conversation): string
    {
        $history = $conversation->messages()
            ->orderByDesc('created_at')
            ->limit(self::MAX_HISTORY_MESSAGES)
            ->get()
            ->sortBy('created_at')
            ->values()
            ->map(fn (Message $message) => [
                'role' => $message->direction === Message::DIRECTION_INBOUND ? 'user' : 'assistant',
                'content' => $message->body,
            ])
            ->all();

        $response = Http::withHeaders([
            'x-api-key' => $this->apiKey,
            'anthropic-version' => '2023-06-01',
        ])->post('https://api.anthropic.com/v1/messages', [
            'model' => $this->model,
            'max_tokens' => 1024,
            'system' => self::SYSTEM_PROMPT,
            'messages' => $history,
        ]);

        if (! $response->successful()) {
            throw new AiDraftingFailedException('Claude API request failed: '.$response->body());
        }

        $draft = trim((string) $response->json('content.0.text'));

        if ($draft === '') {
            throw new AiDraftingFailedException('Claude returned an empty draft.');
        }

        return $draft;
    }
}
```

```php
<?php

namespace App\Services\AI;

use App\Exceptions\AI\AiConfidenceCheckFailedException;
use App\Models\Conversation;
use App\Models\Message;
use Illuminate\Support\Facades\Http;

class JevAdapter
{
    public function __construct(
        private readonly string $apiKey,
    ) {
    }

    public function evaluateConfidence(Conversation $conversation, string $draft): float
    {
        $transcript = $conversation->messages()
            ->orderBy('created_at')
            ->get()
            ->map(fn (Message $message) => ($message->direction === Message::DIRECTION_INBOUND ? 'Customer' : 'Agent').': '.$message->body)
            ->implode("\n");

        $response = Http::withToken($this->apiKey)->post('https://api.typesafe.ai/v1/systemone', [
            'state' => $transcript."\n\nDrafted reply: ".$draft,
            'model' => 'jev-latest',
            'questions' => [
                'confident_to_send' => [
                    'type' => 'noul',
                    'instructions' => 'Given the conversation and the drafted reply, is this reply confident and appropriate to send to the customer as-is?',
                    'criteria' => [
                        'true' => 'confident and appropriate to send',
                        'false' => 'uncertain, incorrect, or needs a human',
                    ],
                ],
            ],
        ]);

        if (! $response->successful()) {
            throw new AiConfidenceCheckFailedException('Jev API request failed: '.$response->body());
        }

        $score = $response->json('answers.confident_to_send.noul');

        if (! is_numeric($score)) {
            throw new AiConfidenceCheckFailedException('Jev response missing a numeric confidence score.');
        }

        return (float) $score;
    }
}
```

```php
<?php

namespace App\Services\AI;

use App\Exceptions\AI\AiConfidenceCheckFailedException;
use App\Exceptions\AI\AiDraftingFailedException;
use App\Jobs\SendTelegramReplyJob;
use App\Models\Conversation;
use App\Models\HandoffEvent;
use App\Models\Message;
use Illuminate\Support\Facades\DB;

class AiReplyService
{
    public function __construct(
        private readonly ClaudeAdapter $claudeAdapter,
        private readonly JevAdapter $jevAdapter,
        private readonly float $confidenceThreshold,
    ) {
    }

    public function handle(Conversation $conversation): void
    {
        // Cheap early exit: if a human already claimed this conversation
        // before the job even started, don't call any external APIs at all.
        $conversation->refresh();
        if ($conversation->owner_type !== Conversation::OWNER_AI) {
            return;
        }

        try {
            $draft = $this->claudeAdapter->draft($conversation);
        } catch (AiDraftingFailedException) {
            $this->handoff($conversation, null, 'ai_error');
            return;
        }

        try {
            $score = $this->jevAdapter->evaluateConfidence($conversation, $draft);
        } catch (AiConfidenceCheckFailedException) {
            $this->handoff($conversation, $draft, 'ai_error');
            return;
        }

        if ($score >= $this->confidenceThreshold) {
            $this->send($conversation, $draft);
        } else {
            $this->handoff($conversation, $draft, 'low_confidence');
        }
    }

    /**
     * Both Claude and Jev are multi-second external calls. A human can
     * claim the conversation while we're waiting on either — re-check
     * ownership under a row lock immediately before writing anything, so
     * stale AI work never overwrites a human's in-progress claim.
     */
    private function send(Conversation $conversation, string $draft): void
    {
        DB::transaction(function () use ($conversation, $draft) {
            $locked = Conversation::where('id', $conversation->id)->lockForUpdate()->first();
            if (! $locked || $locked->owner_type !== Conversation::OWNER_AI) {
                return;
            }

            $message = Message::create([
                'conversation_id' => $locked->id,
                'direction' => Message::DIRECTION_OUTBOUND,
                'sender_type' => 'ai',
                'body' => $draft,
                'status' => Message::STATUS_PENDING,
            ]);

            SendTelegramReplyJob::dispatch($message->id);
        });
    }

    private function handoff(Conversation $conversation, ?string $draft, string $reason): void
    {
        DB::transaction(function () use ($conversation, $draft, $reason) {
            $locked = Conversation::where('id', $conversation->id)->lockForUpdate()->first();
            if (! $locked || $locked->owner_type !== Conversation::OWNER_AI) {
                return;
            }

            if ($draft !== null) {
                Message::create([
                    'conversation_id' => $locked->id,
                    'direction' => Message::DIRECTION_OUTBOUND,
                    'sender_type' => 'ai',
                    'body' => $draft,
                    'status' => Message::STATUS_DRAFT,
                ]);
            }

            $fromOwnerType = $locked->owner_type;

            $locked->update(['owner_type' => Conversation::OWNER_UNASSIGNED]);

            HandoffEvent::create([
                'conversation_id' => $locked->id,
                'from_owner_type' => $fromOwnerType,
                'to_owner_type' => Conversation::OWNER_UNASSIGNED,
                'agent_id' => null,
                'reason' => $reason,
                'created_at' => now(),
            ]);
        });
    }
}
```

```php
    public function ingest(Channel $channel, ParsedInboundMessage $parsed): ?Message
    {
        $conversation = null;

        $message = DB::transaction(function () use ($channel, $parsed, &$conversation) {
            if (! $this->recordWebhookEvent($channel, $parsed)) {
                return null; // duplicate delivery — already processed
            }

            $contact = $this->findOrCreateContact($channel, $parsed);
            $conversation = $this->findOrCreateConversation($channel, $contact);

            return Message::create([
                'conversation_id' => $conversation->id,
                'direction' => Message::DIRECTION_INBOUND,
                'sender_type' => 'contact',
                'body' => $parsed->body,
                'external_message_id' => $parsed->externalEventId,
                'status' => Message::STATUS_RECEIVED,
                'raw_payload' => $parsed->rawPayload,
            ]);
        });

        if ($message !== null && $conversation->owner_type === Conversation::OWNER_AI) {
            GenerateAiReplyJob::dispatch($conversation->id);
        }

        return $message;
    }
```

**Why dispatch outside the transaction, not `->afterCommit()` inside it**: `->afterCommit()` looks like the idiomatic fix (defer the queue push until the transaction is durably committed, so a worker never sees a job for data that isn't there yet), but it has a real problem in this codebase specifically: `RefreshDatabase` wraps every test in an outer database transaction that's rolled back at the end, never truly committed — and `DB::transaction()` calls made *inside* that outer test transaction become savepoints, not real commits (the same mechanism the nested-transaction/savepoint pattern elsewhere in this file already relies on). Laravel only fires `afterCommit()` callbacks when the *outermost* transaction commits. Since that never happens under `RefreshDatabase`, a job dispatched with `->afterCommit()` inside `ingest()`'s transaction would **never actually fire during any test** — `Queue::assertPushed()` in this task's own tests (Steps 7-8) would fail.

Dispatching after `DB::transaction()` returns achieves the identical real-world safety property through plain sequential code instead: `DB::transaction()` only returns once its closure has actually committed (or the exception it threw has already propagated, in which case the dispatch line below is never reached at all) — so a worker can never observe a dispatched job for data that didn't commit, in production or in tests, without depending on the transaction-manager's callback timing.

```php
    public function claim(int $conversationId, ClaimService $claimService): void
    {
        $conversation = Conversation::findOrFail($conversationId);

            $claimService->claim($conversation, auth()->user());
            $this->selectedConversationId = $conversationId;

    private function prefillDraftReply(int $conversationId): void
    {
        $latestDraft = Message::where('conversation_id', $conversationId)
            ->where('status', Message::STATUS_DRAFT)
```
